# 主控设备老化工具

从统一启动页选择“主控设备老化工具”，或在工程根目录执行：

```sh
python -m src.master_aging.bootstrap
```

PC 使用工程现有的 PyQt5、Paramiko、PyYAML 等依赖，无新增 pip 依赖。

## 分层与集成边界

| 目录 | 职责 |
| --- | --- |
| `gui/` | 设备选择、计划编辑、实时曲线/状态、电源确认弹窗、历史统计 |
| `application/` | 批量编排、短命令控制、断线恢复、记录补采 |
| `domain/` | 计划校验、结果规则、身份与配置摘要；无 Qt/SSH 依赖 |
| `adapters/` | 发现协议适配、独立 SSH/SFTP、设备端 zipapp 部署 |
| `device_agent/` | Linux 本地调度、只读采集、负载进程、保护与写入预算 |
| `infrastructure/` | 独立配置、SQLite 事务、CSV/JSON 与离线 HTML |

原有业务代码仅在 `main.py` 增加延迟导入入口、启动页增加按钮和滚动区，打包脚本增加设备端 zipapp 资源。复用现有发现接口与纯 4G 解析代码，不调用 `DeviceTester`、产测初始化、MAC 烧写、标签打印、业务清理、电池解锁或休眠配置。原产测配置仅用于读取 SSH 连接参数及现有发现参数，不写入主控配置单例和芯片缓存。老化配置位于 `config/master_aging/config.yaml`。

点击“保存计划”会立即将项目选择、时长、负载、环境与选填保护等配置写入上述文件，下次启动自动恢复并校验，可直接开始选中设备。取消编辑不保存；配置写入失败会提示并保留编辑窗口。保存采用临时文件替换，避免写入中断破坏原配置；运行中的计划快照不受后续修改影响。

电池行的有效时长只读，按“（充电分钟 + 放电分钟）× 循环数”实时反显，保存时同步写入计算结果；修改任一阶段或循环数后无需手动调整总时长。

充电分钟为 0 时跳过充电、只放电；放电分钟为 0 时跳过放电、只充电，两者不能同时为 0。单方向将各循环时长合并为连续充电或放电，只在开始时确认一次电源条件，不再提示切换到被跳过的阶段；总有效时长仍按上述公式计算，现有完成方式及已启用的保护继续生效。

## 使用流程

1. 点击“子网扫描”，沿用主控产测的局域网扫描方式：单网卡自动扫描所在子网，多网卡时才提示选择设备所在网络；未识别到网卡时使用原发现组件的自动识别/默认子网。扫描完成后可多选或全选添加设备。左侧卡片勾选用于批量运行，点击卡片查看右侧详情和曲线；不使用 hostname 代替设备 `/etc/serial-id`。
2. 在“项目与环境”勾选项目、输入分钟数和电池循环数，无需填写操作人员和工位。CPU/DDR/存储/4G/USB/HDMI 并行、各自到时停止；电池充电和放电按循环串行。温箱设定温湿度只作为条件记录，无实际传感器时不生成实测环境曲线。
3. “保护与夹具（选填）”中的保护门限按项勾选启用，未勾选的门限不参与检查；人工夹具、HDMI 显示、电流方向确认仅作为记录，不阻止保存或启动。默认门限均未启用。USB/HDMI 仍检查实际连接状态，电池仍核验实际电流与采样数据。
4. 在“项目设置”通过输入框、数字框和下拉框设置采集间隔、CPU/DDR 负载、存储测试目录与写入量、电池完成方式。勾选多少台设备就同时老化多少台，无需另设并行台数，旧配置中的台数限制不再生效。界面不提供 YAML 编辑器；日志空间、执行器等内部参数由程序管理。4G 沿用产测的模组识别与信号判定，默认使用内置模组表，无需配置数据接口或探测 IP。保存后冻结本次快照；运行中修改只影响下一次运行。
5. “读取设备信息”用于刷新真实 SN、机型、内存、存储和工具状态；勾选设备时批量读取，未勾选时读取当前查看的设备，读取过程中按钮显示进度并防止重复点击。此步骤可跳过，开始时会自动读取。点击“开始选中设备”后，工具核验 SN、按所选项目使用设备现有软件源自动安装缺失依赖、复检，再启动设备预检并持有独占锁；界面和本地日志显示准备过程及失败原因。仅实际启用并运行电池测试时，首次进入 `WAIT_OPERATOR`（等待电源确认）自动打开弹窗，每台设备每次测试只确认一次，主窗口不常驻确认按钮。充电阶段人工接入适配器，放电阶段人工拔除适配器并接好放电负载，在弹窗中逐台点击“电源已就绪”，无需填写确认人，也无需勾选设备。多台设备在同一非阻塞弹窗中展示，可继续在主窗口监控或停止；选择“稍后处理”后，点击对应设备卡片可重新打开。设备收到确认后直接进入 `RUNNING` 按配置时长计时，不再等待启动电流门限或连续达标次数；充放电阶段与循环切换后也直接计时，不再弹窗或等待电流。旧配置中的启动电流、启动采样次数及启动等待超时字段不再参与执行或校验。确认命令发送失败会在重连后自动补发。设备结束、停止或断线时移除相应待确认提示。界面显示当前充放电阶段、电流和电源操作提示；工具不会自动切换物理电源。电流仍正常采集，已有方向异常检查、完成方式和已启用的保护继续生效；等待首次人工确认、读取缺失区间不计入电池有效时长。
6. 可停止单设备或全部设备；关闭窗口可选择停止并等待，或保留设备端运行并退出。离线停止会排队等待重连，界面不会把未确认停止显示为完成。
7. 点击当前设备的“执行日志”，或在历史记录选中运行后点击“执行日志”，可在非阻塞窗口查看执行过程、4G AT 原始响应及连接部署日志，每两秒增量刷新；窗口限制显示行数，“保存完整执行日志”可保存完整记录。CPU/DDR 等原始 stdout/stderr 在运行结束、附件同步后显示在独立页签，也可通过“打开本次目录”查看。历史记录还可查看报告、生成批次汇总，或对未结束运行“恢复补采”（可填写变化后的 IP）。重连核验 SN/指纹/配置摘要/boot_id，按日志序号幂等补采，禁止再次启动原负载。设备重启或执行器退出会保留中断结论。

报告的事件时间线按设备事件序号展示本地时间（含 UTC 偏移）、累计用时、项目、事件结果和中文说明；完整原始事件默认折叠，采样仍保留在 CSV/JSON 中。累计用时按同次设备启动的首条记录计算，与各项目的有效测试时长分别展示。历史报告重新点击“HTML 报告”即可使用新布局生成，原始判定不变。

项目到时、人工停止和执行异常都会回收本次创建的 CPU、DDR、fio 负载。CPU/DDR 的 stress-ng 超时与计划时长一致，到时先留出 5 秒等待其自行汇总退出，再进行停止清理。正常停止先通知负载主进程收尾，超过 5 秒仍有运行进程则强制终止本次进程组；随后核验整组没有运行进程，包括父进程已退出时遗留的 worker。非零退出（包括强制终止）仍不能判为通过。DDR 启动前记录整机 swap 基线，采样时同时记录本次进程组各进程的 RSS 和 VmSwap。整机 swap 增长仅保留为诊断证据；实际执行 VM 校验的 worker 出现 VmSwap 才因换出判为不完整，wrapper、stress-ng 控制进程的闲置页和其他业务换出不会单独中止测试。进程内存采样失败仍判为不完整，周期采样不是全程逐页驻留证明。停止失败的进程保留引用并在最终清理重试；状态中的 `process_cleanup` 记录进程组和核验结果，无法确认时 `cleanup_confirmed=false`，不能判为通过。不会按进程名称批量结束主控上的其他服务。

电源确认提交后立即唤醒 PC 控制线程；设备由独立控制线程核验确认所属阶段和序号，立即发布运行状态并开始计时，不等待系统采集、电池寄存器读取或 4G 采集。PC 在提交后的 5 秒内加快查询，收到确认状态后恢复常规轮询；状态显示先于日志补采。界面日志分别记录“已提交”和“设备已收到”。传感器仍按配置间隔采集并执行保护；首次采样前不补造电流/电量积分，读取失败或超长采样缺口不计有效时长。

## 设备要求与各项覆盖

设备需要 Linux、SSH/SFTP、可读 `/proc` 和 `dmesg`，并允许在 `/var/tmp/master-aging` 保存受控数据；启用 CPU 温度保护时还需可读 thermal zone。Python 缺失或低于 3.8 时，先通过 shell 核验 SN，再尝试从设备现有软件源安装 Python 3 并核验版本及必要标准库。zipapp 在 PC 根据当前源码生成并通过 SFTP 上传，SHA-256 核验后执行。所有负载创建独立进程组，停止只针对本运行；Linux 父进程死亡信号用于避免执行器意外退出后继续保留直接负载进程。保护线程独立于 SSH 与主采样循环，执行已启用的温度保护，同时监控采样超时、空间、日志上限及 CPU/DDR 到期时间。

| 项目 | 当前实现与预检条件 |
| --- | --- |
| CPU | 缺少 `stress-ng` 时自动安装；`--verify`、CPU 方法集合、按在线核数启动；采集 user/system/iowait、频率、负载及温度；宽限后低于目标不通过 |
| DDR | stress-ng VM 全方法与校验；分配量受总内存比例上限限制，同时保留至少 30% 当前可用内存及配置的最小预留空间（取较大者）；启动时复核限额；检测 worker swap、退出码、OOM |
| SSD/eMMC | 缺少 fio、findmnt 时自动安装；需可核验的内置盘序列号/CID；只在明确目录中创建本 run_id 文件；固定 io_size、crc32c、direct I/O、fsync、JSON 字节数核验；不裸写、不格式化 |
| 4G | 沿用产测的 ATI 识别及按响应格式试读兜底；周期读取移远 QENG/龙尚 CPSI，统一按 RSRP ≥ −90 dBm、SINR ≥ 5 dB、RSRQ ≥ −13 dB 判定；保存原始 AT 响应并拒绝抢占已占用串口 |
| 电池 | hisi 用 i2c-2，wdse 用 i2c-0，SBS 0x0b 只读；有符号净电流、温度/容量模式/原始寄存器、可选厂商型号；每次运行一次人工电源确认后直接计时，连续停止电流检测、固定时长或停止节点模式、mAh/Wh 梯形积分、本地保护 |
| USB | 周期核验非 root-hub 的超速设备，记录夹具身份、协商速率和 devnum，掉线/重枚举留下故障 |
| HDMI | 3S 自动发现 DRM HDMI 路径、connected、EDID 摘要和 modes，记录人工显示确认；hisi 标记 `NOT_APPLICABLE` |

存储测试目录必须已存在，且直接位于可核验的内置盘文件系统上。根目录使用 overlay 的设备应优先选择独立数据分区上的目录，例如 `/data`；`/root` 即使最终写入内置盘，也不作为 direct I/O 压测目标。老化日志目录 `/var/tmp/master-aging` 允许使用 overlay，但须能通过其可写 `upperdir` 核验到底层唯一内置盘及序列号/CID；报告保留原挂载和写入层信息，不能核验时仍阻止启动。

自动部署使用设备已配置的软件源，支持 apt-get、dnf、yum、apk、opkg；需要 root 或免密 sudo。只安装所选项目缺少的依赖：CPU/DDR 对应 stress-ng，存储对应 fio 与 util-linux，电池对应 i2c-tools；USB、HDMI、4G 无额外联网检测依赖。包管理器按目标架构解析软件包，程序不改写软件源，不执行全系统升级。安装后复检命令、Python 版本、fio 身份和 findmnt 版本；软件源、权限或版本不满足时记录具体原因并阻止启动。安装信息保存在硬件快照及报告中，正式投产前仍需在样机验证工具兼容性。恢复补采或运行中重连不会再次安装依赖或启动负载。硬件识别要求设备树或 cpuinfo 能确认 RK3576/310P 且与 SN 前缀一致；未知机型阻止运行。

电池按充电为正、放电为负处理净电流，人工核验勾选为可选记录。已启用的保护触发后停止软件负载并提示接回适配器；没有继电器/电子负载时不能物理断开电池负载。电池项目提前完成后，剩余综合负载运行期间仍执行已启用的电池保护。未设 SOC 门限时，放电停止节点按连续低电流判定。Auto Ship/关机时间写入暂不提供。

DDR 当前判定内存正确性，报告明确不提供 STREAM 读/写/拷贝带宽基线。4G 仅沿用产测的模组识别和信号检测，不执行蜂窝联网或吞吐检测。HDMI 不提供采集卡图像或链路误码判定。温箱自动控制、服务端上传、自动电源夹具均未启用。

## 写入预算与故障恢复

示例配置每盘 8 GiB：31 轮 × 256 MiB + 64 MiB 日志预留 + 64 MiB 元数据预留 = 8064 MiB。示例只是结构和算量，不是批准的量产规范。存储调度独立于系统、电池与 4G 采集，写入轮次均匀分布在计划时长内，完成后只读观察至到时。到时先结算已退出 fio 的结果，再停止和回收仍在运行的 fio，禁止继续启动新轮；未完成全部轮次仍为 `INCOMPLETE`，明确的 I/O 或数据校验错误为 `FAIL`。

设备卡片显示电源确认提交/等待响应/运行状态及存储已完成轮数。存储停止原因和 `items.storage.storage_progress` 保留各目标的完成轮数、中断轮实际写入/读取校验字节数、退出码与进程回收证据；不能取得有效 JSON 时明确标记证据缺失，不补造结果。每轮 fio JSON 分别保存为 `storage_<编号>.round-<轮数>.json`，避免中断时误用上一轮的完整结果；未完成轮次继续保留未决写入预留，不计为校验通过。

“停止选中设备”仅请求停止对应运行，“停止整批”请求停止所有本地活动运行；离线设备在重连后补发停止命令。设备独立控制线程处理停止，不等待系统、电池或 4G 采集返回，先通知全部本次负载停止，再逐组回收。确认进程组已停止并读取结果后，删除该 run_id 创建的 `.master-aging-<run_id>.bin` 临时文件；日志、各轮 JSON 和写入账本继续保留。回收未确认时保留测试文件，最终重试回收；删除失败记录在 `file_cleanup_errors`，设备卡片同时显示进程回收和临时文件清理结果。清理临时文件不会清除未决写入预留。

每轮启动 fio 前，先 fsync 持久化该盘累计账本和本次预留；写完读取校验及实际字节数都通过后结算。设备账本位于 `/var/tmp/master-aging/write-ledger/<存储身份摘要>.json`，累计预留跨运行保留；可设置 `cumulative_write_budget_gib` 限制该盘在本工具记录范围内的累计预算。存在未决预留时，新的存储测试会被预检阻止，需核对原日志和实际写入后由维护人员处理，工具不会自动清零。

账本是本工具的保守主机写入预留记录；系统其他进程写入、文件系统写放大和 NAND 实际写入不能由 fio 字节数精确控制。采样保存原始 diskstats、可读的 eMMC 寿命/预警字段，不根据粗粒度寿命分档推算精确 NAND GiB。删除设备账本会失去累计追踪，应随设备留存，不能当作普通日志清理。

设备独占锁防止本工具多个 PC 同时启动该设备。旧版产测工具和其他程序不遵守此锁，仍应避免并发操作设备；不再通过人工勾选阻止计划保存。本次未修改原产测设备连接流程。

## 本地数据与报告

```text
logs/master_aging/
  aging.sqlite3                       # 独立 SQLite，WAL、串行事务
  <batch_id>/
    batch_report.html
    <safe_sn>/<run_id>/
      manifest.json                    # 真实身份、工具包及配置摘要
      config_snapshot.json
      summary.json
      controller.log
      execution.log                    # 可读事件、逐次采样、4G 原始响应与结束原因
      record_offset.json               # 断线增量游标，DB 提交后更新
      metrics.csv                      # 原始逐字段采样，含接收时间
      records.json                     # 完整事件与采样
      checksums.json
      report.html                      # 内嵌样式、SVG 曲线，完全离线
      device/                          # 原始设备端日志、fio JSON 与请求
```

数据库以 `run_id` 追加历史，以 `(run_id, seq)` 去重；同序号不同内容会报证据冲突。数据表为 batch、run、record、item_run、write_ledger。配置和报告不保存 SSH 凭据。状态/事件立即提交，缺失数据保留 null，报告曲线按桶保留极值，原始数据始终另存。异常、取消、离线退出都能生成带明确状态的报告；最终日志缺段不能判 PASS。

每次导出报告都会生成 `execution.log`，报告提供可读执行日志、连接部署日志及设备原始 `.log` 的链接。旧记录重新导出也能根据已保存的事件与采样生成可读日志；历史数据中未采集的信息不会补造。4G 每次启动均重新执行 AT 模组识别、信号读取和统一阈值预检，不读取上次的通过/失败状态；预检失败会阻止本次设备老化，记录可读原因及 AT 原始证据。每次串口读取结束（包括异常）都会关闭文件描述符并释放锁。

整机结果为适用项目全部完成并通过才 `PASS`；确证故障 `FAIL`，人工停止 `ABORTED`，证据或有效时长不足 `INCOMPLETE`，预检不足 `BLOCKED`，无接口 `NOT_APPLICABLE`。清理不能确认也不能通过。产测服务和业务数据不由本工具改写，无需调用旧产测结束清理。

```sh
python build.py
```
