# 主控设备老化工具

从统一启动页选择“主控设备老化工具”，或在工程根目录执行：

```sh
python -m src.master_aging.bootstrap
```

PC 使用工程现有的 PyQt5、Paramiko、PyYAML 等依赖，无新增 pip 依赖。

## 分层与集成边界

| 目录 | 职责 |
| --- | --- |
| `gui/` | 设备选择、计划编辑、实时曲线/状态、电源切换确认、历史统计 |
| `application/` | 批量编排、短命令控制、断线恢复、记录补采 |
| `domain/` | 计划校验、结果规则、身份与配置摘要；无 Qt/SSH 依赖 |
| `adapters/` | 发现协议适配、独立 SSH/SFTP、设备端 zipapp 部署 |
| `device_agent/` | Linux 本地调度、只读采集、负载进程、保护与写入预算 |
| `infrastructure/` | 独立配置、SQLite 事务、CSV/JSON 与离线 HTML |

原有业务代码仅在 `main.py` 增加延迟导入入口、启动页增加按钮和滚动区，打包脚本增加设备端 zipapp 资源。复用现有发现接口与纯 4G 解析代码，不调用 `DeviceTester`、产测初始化、MAC 烧写、标签打印、业务清理、电池解锁或休眠配置。原产测配置仅用于读取 SSH 连接参数及现有发现参数，不写入主控配置单例和芯片缓存。老化配置位于 `config/master_aging/config.yaml`。

## 使用流程

1. 点击“子网扫描”，沿用主控产测的局域网扫描方式：单网卡自动扫描所在子网，多网卡时才提示选择设备所在网络；未识别到网卡时使用原发现组件的自动识别/默认子网。扫描完成后可多选或全选添加设备。左侧卡片勾选用于批量运行，点击卡片查看右侧详情和曲线；不使用 hostname 代替设备 `/etc/serial-id`。
2. 配置项目及正整数分钟数，无需填写操作人员和工位。CPU/DDR/存储/4G/USB/HDMI 并行、各自到时停止；电池充电和放电按循环串行。并发设备数可在详细参数设置，默认 4 台。
3. 按硬件批准规格填写保护值，并确认设备未被其他程序占用。默认门限为 `null`，不能直接启动。温箱设定温湿度只作为条件记录，无实际传感器时不生成实测环境曲线。
4. 在“详细参数”填写存储实际目录、每盘预算/轮数、4G 数据接口/独占诊断 AT 口/批准的探测 IP。保存后冻结本次快照；运行中修改只影响下一次运行。
5. 开始后设备再次预检并持有独占锁。电池进入 `WAIT_OPERATOR` 时，勾选对应设备并逐台“确认电源切换”。等待人工、等待连续启动电流、读取缺失区间不计入电池有效时长。
6. 可停止单设备或全部设备；关闭窗口可选择停止并等待，或保留设备端运行并退出。离线停止会排队等待重连，界面不会把未确认停止显示为完成。
7. 在历史记录查看报告、生成批次汇总，或对未结束运行“恢复补采”（可填写变化后的 IP）。重连核验 SN/指纹/配置摘要/boot_id，按日志序号幂等补采，禁止再次启动原负载。设备重启或执行器退出会保留中断结论。

## 设备要求与各项覆盖

设备需要 Linux、Python 3.8+、SSH/SFTP、可读 `/proc`、thermal zone 和 `dmesg`，并允许在 `/var/tmp/master-aging` 保存受控数据。zipapp 在 PC 根据当前源码生成并通过 SFTP 上传，SHA-256 核验后执行。所有负载创建独立进程组，停止只针对本运行；Linux 父进程死亡信号用于避免执行器意外退出后继续保留直接负载进程。保护线程独立于 SSH 与主采样循环，监控温度、采样超时、空间、日志上限及 CPU/DDR 到期时间。

| 项目 | 当前实现与预检条件 |
| --- | --- |
| CPU | 设备需预装已验证的 `stress-ng`；`--verify`、CPU 方法集合、按在线核数启动；采集 user/system/iowait、频率、负载及温度；宽限后低于目标不通过 |
| DDR | stress-ng VM 全方法与校验；分配量取总内存比例上限和 `MemAvailable - reserve` 较小值；检测 swap、退出码、OOM |
| SSD/eMMC | 需已验证的 fio、findmnt、可核验的内置盘序列号/CID；只在明确目录中创建本 run_id 文件；固定 io_size、crc32c、direct I/O、fsync、JSON 字节数核验；不裸写、不格式化 |
| 4G | 独占诊断 AT 口，拒绝抢占已有进程；复用移远 QENG/龙尚 CPSI 解析及统一阈值；周期采集 ATI、SIM、CEREG、信号、路由及绑定蜂窝接口的有限 ICMP、接口字节计数 |
| 电池 | hisi 用 i2c-2，wdse 用 i2c-0，SBS 0x0b 只读；有符号净电流、温度/容量模式/原始寄存器、可选厂商型号；连续启动/停止确认、固定时长或停止节点模式、mAh/Wh 梯形积分、本地保护 |
| USB | 周期核验非 root-hub 的超速设备，记录夹具身份、协商速率和 devnum，掉线/重枚举留下故障 |
| HDMI | 3S 自动发现 DRM HDMI 路径、connected、EDID 摘要和 modes，记录人工显示确认；hisi 标记 `NOT_APPLICABLE` |

CPU/DDR/fio 工具必须由样机验证后离线安装到设备 PATH。仓库不附带来源、架构或许可证未经核验的二进制文件，也不在设备运行时联网安装软件。硬件识别要求设备树或 cpuinfo 能确认 RK3576/310P 且与 SN 前缀一致；未知机型阻止运行。

电池需先在样机核验正负电流方向。保护后停止软件负载并提示接回适配器；没有继电器/电子负载时不能物理断开电池负载。电池项目提前完成后，剩余综合负载运行期间仍保留电池保护。Auto Ship/关机时间写入暂不提供，避免沿用现有产测上锁“退出码即成功”的规则冒充已验证回读。

DDR 当前判定内存正确性，报告明确不提供 STREAM 读/写/拷贝带宽基线。4G 当前覆盖控制面和绑定接口的 ICMP，不宣称 DNS/TCP/HTTPS 或吞吐压测通过；探测失败仅保留证据，不自动认定天线/模组为唯一原因。HDMI 不提供采集卡图像或链路误码判定。温箱自动控制、服务端上传、自动电源夹具均未启用。

## 写入预算与故障恢复

示例配置每盘 8 GiB：31 轮 × 256 MiB + 64 MiB 日志预留 + 64 MiB 元数据预留 = 8064 MiB。示例只是结构和算量，不是批准的量产规范。写入轮次均匀分布在计划时长内，完成后只读观察至到时；到时仍有未完成轮次则 `INCOMPLETE`。

每轮启动 fio 前，先 fsync 持久化该盘累计账本和本次预留；写完读取校验及实际字节数都通过后结算。设备账本位于 `/var/tmp/master-aging/write-ledger/<存储身份摘要>.json`，累计预留跨运行保留；可设置 `cumulative_write_budget_gib` 限制该盘在本工具记录范围内的累计预算。存在未决预留时，新的存储测试会被预检阻止，需核对原日志和实际写入后由维护人员处理，工具不会自动清零。

账本是本工具的保守主机写入预留记录；系统其他进程写入、文件系统写放大和 NAND 实际写入不能由 fio 字节数精确控制。采样保存原始 diskstats、可读的 eMMC 寿命/预警字段，不根据粗粒度寿命分档推算精确 NAND GiB。删除设备账本会失去累计追踪，应随设备留存，不能当作普通日志清理。

设备独占锁防止本工具多个 PC 同时启动该设备。旧版产测工具和其他程序不遵守此锁，因此必须按界面确认的要求避免并发操作设备；本次未修改原产测设备连接流程。

## 本地数据与报告

```text
logs/master_aging/
  aging.sqlite3                       # 独立 SQLite，WAL、串行事务
  <batch_id>/
    batch_report.html
    <safe_sn>/<run_id>/
      manifest.json                    # 真实身份、工具包及配置摘要
      config_snapshot.json
      summary.json
      controller.log
      record_offset.json               # 断线增量游标，DB 提交后更新
      metrics.csv                      # 原始逐字段采样，含接收时间
      records.json                     # 完整事件与采样
      checksums.json
      report.html                      # 内嵌样式、SVG 曲线，完全离线
      device/                          # 原始设备端日志、fio JSON 与请求
```

数据库以 `run_id` 追加历史，以 `(run_id, seq)` 去重；同序号不同内容会报证据冲突。数据表为 batch、run、record、item_run、write_ledger。配置和报告不保存 SSH 凭据。状态/事件立即提交，缺失数据保留 null，报告曲线按桶保留极值，原始数据始终另存。异常、取消、离线退出都能生成带明确状态的报告；最终日志缺段不能判 PASS。

整机结果为适用项目全部完成并通过才 `PASS`；确证故障 `FAIL`，人工停止 `ABORTED`，证据或有效时长不足 `INCOMPLETE`，预检不足 `BLOCKED`，无接口 `NOT_APPLICABLE`。清理不能确认也不能通过。产测服务和业务数据不由本工具改写，无需调用旧产测结束清理。

## 打包

```sh
python build.py
```

打包脚本将同份设备源码生成 `master_aging_agent.pyz` 嵌入应用，独立配置沿现有 config 目录一并发布。无需从开发机绝对路径读取脚本。

正式发布前需在两款设备分别完成工具/ABI、传感器、限值、I2C、夹具、断电/重连和长时老化联调。
